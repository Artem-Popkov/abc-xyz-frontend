# ABC/XYZ-анализ запасов — фронтенд

Фронтенд учебного проекта по кейсу 12 «Учёт затрат и ABC/XYZ-анализ». Менеджер загружает справочник товаров и продажи по чекам и за минуту видит, какие товары приносят деньги (ABC), какие продаются стабильно (XYZ) и что с ними делать.

Стек: React + Vite, JavaScript, Material UI, Recharts. Стиль — Apple TV / tvOS, светлая и тёмная темы.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev       # http://localhost:5173
```

По умолчанию расчёт идёт на моке прямо в браузере, бэкенд не нужен.

```bash
npm run build     # сборка в dist/
npm run lint      # проверка кода (oxlint)
npm run preview   # просмотр сборки
```

## Как пользоваться

1. **Обложка** → «Попробовать на примере» (сразу покажет результат) или «Начать анализ».
2. **Данные**: перетащите `items.csv` и `sales.csv` (вместе или по одному) или нажмите «Загрузить пример». Строки с ошибками пропускаются, их список можно раскрыть.
3. **Настройки расчёта** (раскрывающаяся панель): пороги ABC (A < 80 %, B < 95 %), XYZ (X: CV < 0,10, Y: CV < 0,25), период «с — по».
4. **Рассчитать** → **Результаты**: KPI, матрица 3×3 с советами (клик по группе фильтрует таблицу), кривая Парето, доли A/B/C и X/Y/Z, таблица с поиском и фильтрами, кнопка «Скачать CSV».

Тема переключается кнопкой ☀️/🌙 в шапке.

## Формат данных

- `items.csv`: `item_code, name, category`
- `sales.csv`: `doc_id, date, item_code, qty, price` (дата `ГГГГ-ММ-ДД`)

Пример — `docs/sample/`. Все правила и проверки — `docs/data-format.md`.

## Формулы

- Выручка товара = Σ qty × price за период.
- **ABC:** товары по убыванию выручки; если накопленная доля **предыдущих** товаров < 80 % → A, < 95 % → B, иначе C.
- **XYZ:** продажи (шт.) по месяцам периода, месяцы без продаж = 0. CV = σ / μ (σ по N). CV < 0,10 → X, < 0,25 → Y, иначе Z. Меньше 3 месяцев с продажами → «–».
- Экспорт CSV: `item_code, name, revenue, abc, cv, xyz, class`.

Методика совпадает с программой бэкенда. Подробности и допущения — `docs/DECISIONS.md`.

## Переменные окружения

Файл `.env` создаётся из `.env.example` (сам `.env` в git не попадает).

| Переменная | По умолчанию | Что делает |
|------------|--------------|------------|
| `VITE_USE_MOCKS` | мок | Любое значение, кроме `false`, — расчёт на моке. `false` — запрос на `VITE_API_URL` |
| `VITE_API_URL` | пусто | Адрес бэкенда, например `http://localhost:8000` |
| `VITE_MOCK_ERROR` | `false` | `true` — мок имитирует ошибку сервера (проверка «Повторить») |

## Подключение бэкенда

1. Бэкенд реализует `POST /api/analysis` по `docs/api-contract.md` и разрешает CORS.
2. В `.env`: `VITE_USE_MOCKS=false`, `VITE_API_URL=<адрес>`.
3. Если формат другой, правится только `src/api/` (`client.js`, `buildRequest.js`).

Требования к бэкенду (HTTP-сервер, пороги в параметрах, CORS) и нерешённые вопросы — в `docs/DECISIONS.md`.

## Структура

```
src/
  api/          client.js — связь с бэкендом (мок или сеть), mockServer.js — мок,
                buildRequest.js — тело запроса, errors.js
  components/   матрица, Парето, сводка классов, таблица, KPI, загрузка файлов,
                настройки, фон со свечением
  pages/        CoverPage, InputPage, ResultsPage
  hooks/        тема (useColorMode), набегающие числа (useCountUp)
  utils/        analysis.js — расчёт, csv.js — разбор и проверки,
                exportCsv.js, format.js, classes.js — советы и цвета групп
  mocks/        sampleData.js — пример данных
  theme.js      светлая и тёмная темы
docs/           контракт API, формат данных, решения, пример данных
```

## Ограничения MVP

Без прогнозов спроса, нейросетей, авторизации и микросервисов (решение тимлида). Не сделаны пузырьковая диаграмма XYZ и фильтр по диапазону выручки — см. `docs/DECISIONS.md`.
