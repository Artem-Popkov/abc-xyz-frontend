# Контракт API: POST /api/analysis

Версия 2 (25.10.2026). Подстроена под формат данных и методику бэкенда (консольная программа на Go). **Пока не подтверждена бэкендом**: фронт работает на моке, который отвечает ровно в этом формате (`src/api/mockServer.js`).

Всё, что касается HTTP, живёт в `src/api/`: если формат поменяется, правятся только `client.js`, `buildRequest.js` и `mockServer.js`.

## Общее

- `POST {VITE_API_URL}/api/analysis`, заголовок `Content-Type: application/json`, ответ — JSON.
- **CORS:** бэкенд разрешает `Origin` фронта: `http://localhost:5173` (разработка) и `https://<логин>.github.io` (GitHub Pages). Нужны заголовки `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods: POST, OPTIONS`, `Access-Control-Allow-Headers: Content-Type`, и ответ `204` на `OPTIONS` (preflight).
- **Все доли и пороги — дроби**: `0.8` = 80 %. Так же, как в программе бэкенда.
- Месяц — строка `ГГГГ-ММ`, дата — `ГГГГ-ММ-ДД`.

## Запрос

Фронт сам разбирает `items.csv` и `sales.csv` и присылает уже проверенные строки (как проверяет — см. `docs/data-format.md`). Бэкенд всё равно проверяет их ещё раз.

```json
{
  "params": {
    "abc": { "a": 0.8, "b": 0.95 },
    "xyz": { "x": 0.1, "y": 0.25 },
    "from": null,
    "to": null
  },
  "items": [
    { "item_code": "P001", "name": "Кофе в зёрнах 1 кг", "category": "Бакалея" }
  ],
  "sales": [
    { "doc_id": "CHK-0001", "date": "2025-09-05", "item_code": "P001", "qty": 6, "price": 1000 }
  ]
}
```

| Поле | Тип | Смысл |
|------|-----|-------|
| `params.abc.a`, `params.abc.b` | число 0…1 | Пороги ABC: `A`, если накопленная доля **до** товара `< a`; `B`, если `< b`; иначе `C`. По умолчанию 0.8 и 0.95 |
| `params.xyz.x`, `params.xyz.y` | число > 0 | Пороги XYZ по CV: `X`, если `CV < x`; `Y`, если `CV < y`; иначе `Z`. По умолчанию 0.1 и 0.25 |
| `params.from`, `params.to` | `"ГГГГ-ММ"` или `null` | Период (как флаги `-from`/`-to`). `null` — от первого / до последнего месяца с продажами |
| `items[]` | массив | Справочник: `item_code` (обязателен), `name`, `category` |
| `sales[]` | массив | Продажи: `doc_id`, `date`, `item_code`, `qty` (> 0), `price` (≥ 0) |

## Ответ 200

Пример — ответ на тестовый набор бэкенда (6 товаров, 34 строки продаж за сентябрь–декабрь 2025) с порогами по умолчанию; цифры совпадают с расчётом по формулам бэкенда:

```json
{
  "params": {
    "abc": { "a": 0.8, "b": 0.95 },
    "xyz": { "x": 0.1, "y": 0.25 },
    "from": "2025-09",
    "to": "2025-12",
    "months": 4,
    "calculatedAt": "2026-10-25T14:03:00Z"
  },
  "items": [
    {
      "item_code": "P001", "name": "Кофе в зёрнах 1 кг", "category": "Бакалея",
      "revenue": 50000, "share": 0.5, "cumulativeShare": 0.5,
      "avgQty": 12.5, "activeMonths": 4, "cv": 0.132665,
      "abc": "A", "xyz": "Y", "class": "AY"
    },
    {
      "item_code": "P003", "name": "Хлеб белый", "category": "Выпечка",
      "revenue": 9000, "share": 0.09, "cumulativeShare": 0.89,
      "avgQty": 45, "activeMonths": 4, "cv": 0.333333,
      "abc": "B", "xyz": "Z", "class": "BZ"
    },
    {
      "item_code": "P004", "name": "Ёлочные игрушки (набор)", "category": "Сезонные товары",
      "revenue": 6000, "share": 0.06, "cumulativeShare": 0.95,
      "avgQty": 5, "activeMonths": 1, "cv": null,
      "abc": "B", "xyz": "-", "class": "B-"
    }
  ],
  "summary": { "items": 6, "revenueTotal": 100000, "salesRows": 34 },
  "warnings": []
}
```

| Поле | Смысл |
|------|-------|
| `params` | Параметры, с которыми **фактически** считали (для трассируемости — требование кейса). `from`/`to` — итоговый период, `months` — число месяцев в нём, `calculatedAt` — дата расчёта (ISO 8601) |
| `items[]` | **Все** товары справочника, отсортированные по убыванию выручки, при равенстве — по `item_code`. Товары без продаж тоже есть: `revenue: 0`, класс `C-` |
| `revenue` | Σ qty × price за период, округлено до копеек |
| `share` | Доля товара в выручке (дробь) |
| `cumulativeShare` | Накопленная доля **с учётом** этого товара (для графика Парето). Класс ABC считается по доле **до** товара: `cumulativeShare − share` |
| `avgQty` | Средние продажи в месяц, шт. (месяцы без продаж = 0) |
| `activeMonths` | Сколько месяцев с продажами |
| `cv` | σ/μ, σ по N месяцам (не N − 1), округлено до 6 знаков. `null`, если `activeMonths < 3` |
| `abc` | `"A"`, `"B"`, `"C"` |
| `xyz` | `"X"`, `"Y"`, `"Z"` или `"-"` (меньше 3 месяцев с продажами) |
| `class` | `abc + xyz`, например `"AY"`, `"C-"` |
| `summary` | Число товаров, общая выручка, сколько строк продаж вошло в расчёт |
| `warnings[]` | Строки, которые бэкенд пропустил при своей проверке, текстом: `"sales.csv:12 qty: must be > 0"`. Пусто, если всё хорошо |

## Ошибки

Код 4xx/5xx и тело `{ "error": "понятный текст" }`. Фронт показывает этот текст и кнопку «Повторить».

| Код | Когда |
|-----|-------|
| 400 | Неверный JSON, нет `items`/`sales`, неверные пороги (`0 < a < b < 1`, `0 < x < y`), `from` позже `to` |
| 422 | Нет ни одной корректной продажи в периоде; выручка равна нулю |
| 500 | Внутренняя ошибка |
